# PM Radar

Помощник продукт-менеджера интернет-магазина. На обзоре магазина видны решения по Astra, Kaspersky и Office. Из сигнала Kaspersky можно запустить исследование. Qwen формирует поисковые запросы, выбирает записи и предлагает проверку. Qwen открывает описания задач и объясняет, подходит ли найденная задача. Менеджер открывает основание, выбирает связанную или новую проверку, задаёт владельца и срок. В карточке сохраняются решение, проверка после релиза и фактические токены каждого вызова.

## Запуск на учебных данных

Понадобятся Python 3.11+, openpyxl и для исследования локальная Qwen2.5 Instruct в формате GGUF с llama.cpp. Воронку и карточки можно посмотреть до подключения модели. Команды выполняются из корня клона ветки jury.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install 'openpyxl>=3.1,<4'
python demo/sample_store.py .demo-data/sample
PM_DATA_DIR="$PWD/.demo-data/db" \
PM_EVIDENCE_FILE="$PWD/.demo-data/sample/input.json" \
PM_STORE_FILE="$PWD/.demo-data/sample/store.json" \
PM_RESEARCH_FILE="$PWD/.demo-data/sample/research.json" \
python prototype/app.py
```

Откройте [PM Radar на своём компьютере](http://127.0.0.1:18763). Все числа и интервью в этом режиме вымышлены. Для запуска исследования поднимите модель в другом терминале и оставьте её работать.

```bash
llama-server -m /path/to/qwen2.5-instruct.gguf --host 127.0.0.1 --port 18764 -c 4096 -np 1 --alias pm-local
```

Выберите **Kaspersky → Открыть отклонение → Исследовать Kaspersky с Qwen**. По завершении откройте источник, затем «Принять решение». У подтверждённого совпадения кнопка показывает номер найденной задачи. Для разбора без совпадения можно создать новую задачу или отложить решение. Из сохранённой задачи можно открыть связанную проверку. На защищённом стенде также работает экспорт CSV для Redmine. В находке раскройте «Расход исследования» для просмотра входных и выходных токенов, времени и количества вызовов.

## Запуск с материалами задачи

Ролик по Kaspersky записан в закрытом режиме Qwen3-32B на выданной книге Excel. У организаторов та же версия кода рассчитывает показатели по предоставленным материалам. Сохраните Excel-книги и презентацию в закрытом каталоге `source/`, включая исходную подпапку интервью. Подготовьте файлы для чтения приложением.

```bash
mkdir -p .demo-data/partner
python prototype/store_history.py .demo-data/partner/store.json
python prototype/research_corpus.py .demo-data/partner/research.json
PM_DATA_DIR="$PWD/.demo-data/partner/db" \
PM_STORE_FILE="$PWD/.demo-data/partner/store.json" \
PM_RESEARCH_FILE="$PWD/.demo-data/partner/research.json" \
python prototype/app.py
```

Книги, выгрузки источников, базы, учётные данные, приглашения и файл модели хранятся отдельно от публичного Git. Для локального режима доступна llama.cpp. На стенде жюри разрешённые выборки передаются в Qwen3‑32B через OpenRouter.

На защищённом стенде жюри три кейса используют материалы заказчика и Qwen3‑32B через OpenRouter. В каждой карточке доступны адреса источников, решение ПМа и фактические списания. Открытие готового результата не создаёт нового платного вызова.

## Кейс Kaspersky на данных партнёра

Режим для приглашённых экспертов использует минимальную проекцию двух шестинедельных окон Kaspersky. Чтобы подготовить её на машине, где доступны исходные файлы задачи, из корня репозитория выполните:

```bash
mkdir -p .demo-data/partner
python prototype/store_history.py .demo-data/partner/store.json
python prototype/partner_cloud.py .demo-data/partner/store.json .demo-data/partner/kes-review.json
```

В окружении сервиса демостенда задайте `PM_KES_EXCEL_PROJECTION` путём к файлу `kes-review.json`. Разбор работает в облачных режимах `PM_JURY_CLOUD=public` (по защищённому приглашению) и `staging` (loopback). При смене набора используйте новую базу или перенесите в неё только исследования сохранившихся кейсов. Сырые книги и полный импорт остаются у владельца. В интерфейсе откройте **Kaspersky → Открыть строки Excel → Исследовать с Qwen3‑32B**.

В OpenRouter передаются два агрегата, определение индекса и поля задач-кандидатов. Поиск использует тот же механизм, что и другие кейсы жюри. Приложение сверяет выбранную задачу с исходной строкой, затем модель предлагает критерий технической приёмки и способ оценки продаж. ПМ подтверждает действие. Источники и списания доступны в карточке.

## Три кейса по материалам задачи на стенде жюри

Актуальный стенд использует подготовленную из файлов заказчика проекцию для **всех трёх** кейсов. Для Astra доступны недели Метрики и BI, шаги подбора, интервью и реальный бэклог. Для Office сравниваются предложения по одному артикулу, условия счёта и частичные совпадения. Модель выбирает проверку и подтверждающие записи. Завершённые до исследования задачи не предлагаются как открытые. При отсутствии совпадения ПМ может создать новую проверку.

Подготовьте экспорт, как описано выше, затем выполните:

```bash
python prototype/partner_cloud.py .demo-data/partner/store.json .demo-data/partner/review.json --all-cases
PM_PARTNER_REVIEW="$PWD/.demo-data/partner/review.json" PM_JURY_CLOUD=staging \
PM_DATA_DIR="$PWD/.demo-data/partner-review-db" PM_MODEL_DAILY_LIMIT=24 python prototype/app.py
```

В режиме public тот же файл указывается защищённому сервису с приглашением. Расчётное окружение и хранилище SQLite находятся на сервере, инференс Qwen3-32B выполняется через OpenRouter. Участники жюри используют браузер. Исходные данные и ключи хранятся вне Git.
